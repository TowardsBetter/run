# 胡淏 + AI 跑步教练

==让状态和华为既定课表同时可见；教练真正分析的是每一课该怎样执行。==

打开：Finder 里双击 [[AI+/output（AI+胡淏）/胡淏+AI跑步教练/打开仪表盘.command|打开仪表盘]]（Cursor / Obsidian 里点开这个文件只会看到脚本，不会启动网页）。启动后地址是 http://127.0.0.1:18765/ 。不要直接打开 `web/index.html`。

这是 [[AI+/output（AI+胡淏）/实验|实验]] 里的一次尝试，对齐 [[AI+/认知/Agent怎么跟学习者说话]]：华为 AI 训练计划负责排课，教练基于真实完成、体感、恢复和近期负荷判断怎样执行，不替你编反馈，也不另排第二套课表。长期原则在 [[AI+/output（AI+胡淏）/胡淏+AI跑步教练/data/coach-notebook|教练笔记]]，当天会话存档在 [[AI+/output（AI+胡淏）/胡淏+AI跑步教练/data/coach-log|跑步教练会话]]。

## 页面

上：跑力、华为跑力、本月 100 km 进度与本月统计收在同一个模块；次数、跑量、均配和均心率都固定按自然月 1 日至今天计算。上海天气分成气温和每天跑量两层；湿度默认藏在时间轴悬浮提示里。图下的起止日期只控制天气、跑步 Log 与训练浏览。左栏是一条以粗线为「现在」的时间流：线上是从今天起的接下来 7 天，最远一天在最上、今天贴着线；线下是跑步 Log，今天在最上、越旧越往下。未来与过去使用完全相同的日期行和活动行，未来只保留极淡底色。右栏从上到下是固定的本次训练简报、轻量输入框、倒序训练对话；简报先讲训练、跑姿与恢复，最后接明天和未来 7 天，后续对话不把它冲走。配色以 Tableau 10 为底。

华为 AI 课表来自训练营的只读接口。它必须按自然周读取，不能把整段日期一次请求；每次同步读取从本周起 10 周并写入 `data/huawei_plan.json`。页面是主界面，Markdown 只用于后台存档。

## 刷新数据

在仪表盘上做，不用开终端、不用 F12：

1. 用 Chrome 打开 [华为训练营](https://health.cloud.huawei.com/TrainingCamp#/dashboard) 并登录，能看见跑步记录即可，标签保持开着。
2. 点「更新数据」。本机从 Chrome 的 sessionStorage 读 `accessToken`，再拉跑步、华为 AI 课表、睡眠、心率、天气和跑力。

凭证写在资料库 `runtime/跑步教练/session.json`，不进教学库、不进聊天。过期后重新打开训练营登录，再点更新。`scripts/refresh.sh` 只是备用。

训练记录进资料库 `runtime/跑步教练/coach.sqlite3`（见 [[AI+/output（AI+胡淏）/胡淏+AI跑步教练/schema|数据库]]）。打开仪表盘会自动拉一次；点左边某条训练，曲线从库里读。同一天有两次跑步时，列表会列出两条，刷新也会把当天每一条的曲线都重拉，不再只留最长的那一次。

本项目只读取华为已经排好的课，不向运动健康写课。Health Kit 推课仍处于搁置状态。见 [[AI+/output（AI+胡淏）/胡淏+AI跑步教练/data/log|跑步日志]]。

## 跑力怎么算

仪表盘上的数字是 Jack Daniels / Jimmy Gilbert 的 VDOT，不是实验室测的最大摄氧量。速度 \(v\) 是米/分钟，时间 \(t\) 是分钟：

\[
\mathrm{VO}_2(v) = -4.60 + 0.182258 v + 0.000104 v^{2}
\]

\[
\%\mathrm{VO}_2\mathrm{max}(t) = 0.8 + 0.1894393 e^{-0.012778 t} + 0.2989558 e^{-0.1932605 t}
\]

\[
\mathrm{VDOT} = \mathrm{VO}_2(v) \div \%\mathrm{VO}_2\mathrm{max}(t)
\]

出处：*Oxygen Power*（1979），亦见 *Daniels' Running Formula* 第 4 版。只纳入距离 ≥ 3 km 且时长 ≥ 10 分钟的跑步；轻松跑会低估，看趋势不要看单次。华为自己的跑力指数若拉到了，会写在同一份 `fitness_trend.json` 里对照，不混成一条线。

天气来自 [Open-Meteo](https://open-meteo.com/)，免费、不用 key；上海坐标 31.2304, 121.4737。本次训练大图是 ECharts：每条曲线先做左右各 3 个点的中心移动平均，再画残差约 80% 带。指标表在 [[AI+/output（AI+胡淏）/胡淏+AI跑步教练/web/session-chart.js|session-chart.js]] 的 `METRICS`，窗口在同文件 `SMOOTH`。

## 教练模型

数据文件不含判断。右栏后端每次把华为未来课表、最新训练与详细序列、近 7–30 天负荷、跑姿采样、睡眠、HRV、静息心率、跑力、教练笔记和训练锚点整理给 Cursor Agent；有数据才说，没有就明确留白。自动复盘不假装用户已经说过体感，依次分析训练本身、跑姿 / 力学、恢复 / 负荷，最后给明天执行对策和未来 7 天心态。它以简练的分段训练简报固定在右栏上方；输入框在简报和对话之间，用户记录与教练回复仍按时间倒排，最近一轮在最上。接口没给的目标配速、心率和分步内容不编。

模型运行复用资料库边注阅读的 Cursor SDK 环境与 macOS 钥匙串，不在教学库保存 key 或复制 `.venv`。SDK 未接通时，页面只显示“模型暂时未接通”；后端可以返回数据摘要，但不会用本地规则模板冒充教练。
